# Additions and conflicts from *UI Pedia*

Where it disagrees with Practical UI or project decisions (no gradients, disabled buttons OK), follow those.

## Extra rules
- Typography: define one type scale for web, iOS and Android and share it. Emphasise with bold/italic, not all caps.
- Buttons are for actions; links are for navigation. Do not style interactive and non-interactive elements alike.
- Make the most common action the primary and focused. When risk is high or options equal, give equal weight and no default.
- Button padding: horizontal about 2x vertical; centre labels exactly.
- Gestures (swipe, double-tap, long-press) are shortcuts only; provide a visible alternative.
- Toggle groups need at least 3 items and labels.
- CTA height 40-60pt.
- Hamburger menus can hide navigation; keep primary destinations visible. Prefer mega menus over deep dropdowns on large sites.
- Navigation cues: logo, page title, breadcrumbs, active state. Test with prototypes.
- Forms: only needed fields, logical order (easy first), input masks, inline validation, progress bar, autofill, save progress, no reset button, descriptive labels ("Name on card"), outcome-based button copy, loading state after submit.
- Errors: what is wrong and how to fix; icon plus text.
- Cards: one idea per card, one link/action set, summary under about 100 characters, light borders, consistent high-res images, square on mobile with fewer columns.
- Prototype and test with real users.

## Conflicts (source says X; we follow Y)
| UI Pedia says | We follow |
|---|---|
| Touch 44x44; desktop 32x32 | 48x48pt min |
| Red/green text for errors | Colour + icon + border + text |
| Uppercase button labels OK | Sentence case |
| OK first or last | Most important first, left-aligned |
| Placeholder as hint | Visible labels, hints above |
| Multiple brand colours | One brand colour, interactive only |
