# Prototype Playground: Agent Rules

Read this whole file before you change anything. These rules are not optional.
The app is in `playground/` (repo root: `hw/`). Run every command from `playground/`.

## 0. What this is

A Next.js 16 (App Router, TypeScript, Tailwind v4, shadcn/ui on Base UI, next-themes) app that holds many small, self-contained prototypes. The owner asks for prototypes, often from a phone. You build them and open a pull request. The PR gets a preview deployment.

```
playground/
├── app/
│   ├── page.tsx                  gallery (search, tags, hidden toggle, static thumbnails)
│   ├── layout.tsx                root layout, ThemeProvider (dark default, system respected)
│   ├── login/ api/auth/          password gate (prod only)
│   ├── p/[slug]/                 PUBLIC route: renders a prototype only if metadata.public === true
│   ├── prototypes/[slug]/        catches unknown slugs → 404
│   ├── prototypes/layout.tsx     adds the floating back link
│   ├── prototypes/<slug>/        ONE FOLDER PER PROTOTYPE
│   └── api/<slug>/...            API routes for a prototype (namespace by slug)
├── components/ui/                shadcn/ui: vendored, all components installed. Do not edit.
├── components/playground/        gallery chrome (theme toggle, thumbnail, back link)
├── lib/controls/                 shared control-panel library (schema → panel + persistence + Reset + Randomize)
├── lib/prototypes.ts             reads the generated registry
├── lib/generated/                AUTO-GENERATED by scripts/gen-registry.mjs (gitignored). Never edit.
├── proxy.ts                      Next 16 "middleware": password gate
├── public/thumbnails/            <slug>-light.png, <slug>-dark.png
├── public/og/                    <slug>.png, <slug>.mp4 (public prototypes only)
└── scripts/                      gen-registry, capture-thumbnails, capture-og
```

Discovery is automatic. `scripts/gen-registry.mjs` scans `app/prototypes/*/`. It runs before `dev`, `build`, `lint`, and `typecheck`, and after `install`. A folder is registered only if it has `page.tsx`, `metadata.json`, and `HOW_IT_WORKS.md`. If one is missing, the script prints a warning and skips the folder.

## 1. Create a new prototype (start to pull request)

Never build a "new prototype" button or a create API. Prototypes are created only by an agent, by this procedure:

1. `git checkout -b proto/<slug>` from an up-to-date `main`. The slug is kebab-case.
2. `mkdir app/prototypes/<slug>` and add:
   - `page.tsx`: a thin server page (~10–60 lines) that exports `metadata = { title }` and renders one client root component. It must have a **default export with no required props**, because `/p/<slug>` imports and renders it.
   - `metadata.json` (schema in §2.1). `createdAt` is today, `updatedAt` is the current ISO timestamp, and `public: false`.
   - `HOW_IT_WORKS.md` (sections in §2.2).
   - Split files per §2.3: `types.ts`, `data.ts`, pure logic files, and one file per component.
3. If it has tunable parameters, use `lib/controls` (§2.5). Copy the pattern from `app/prototypes/road-scroll/`.
4. If it needs a server route, put it at `app/api/<slug>/.../route.ts`. The password gate opens `/api/<slug>/*` automatically when the prototype is public.
5. Run `npm run dev`. Check the prototype at 375px and at desktop width, in dark and in light mode.
6. Thumbnails: run `npm run thumbnails -- <slug>`. **Open both PNGs and look at them.** The script hides elements marked `data-capture-hide`. Put that attribute on floating chrome (hints, FABs).
7. Run `npm run check` (lint + typecheck + production build). All three must pass.
8. Commit, including the thumbnails, then `git push -u origin proto/<slug>` and `gh pr create --fill`.
9. Post the Vercel preview link. Get it from the PR (`gh pr view --json comments`, or `gh pr checks`), and post it in the form `<preview-url>/prototypes/<slug>`, so the owner can open it on their phone. If the preview isn't ready yet, post the PR URL and say so.

To edit an existing prototype, do the same: branch, change, bump `updatedAt`, update `HOW_IT_WORKS.md`, regenerate thumbnails if the visuals changed, `npm run check`, then open a PR and post the preview link.

## 2. Rules for every prototype

### 2.1 Metadata
```json
{
  "title": "My Prototype",
  "description": "What it does",
  "tags": ["tag1"],
  "createdAt": "YYYY-MM-DD",
  "updatedAt": "ISO timestamp",
  "hidden": false,
  "public": false
}
```
- Bump `updatedAt` on **every** edit. The gallery sorts by it.
- `hidden: true` removes the prototype from the default gallery view (the Hidden toggle shows it again).
- `public: true` only when the owner explicitly asks for **that specific** prototype to be public. Never make one public on your own initiative.

### 2.2 HOW_IT_WORKS.md
Keep this file current on every change. It has these sections:
- **What It Does**: 1–2 sentences.
- **Architecture**: an ASCII data-flow diagram.
- **Frontend / API**: bullet points on state, shortcuts, responsive behavior, request/response shapes.
- **AI Usage** (if a model is called): model ID, why that model, how it is called, key parameters, system prompt summary, user prompt shape.
- **Key Dependencies**, **Component Tree**, **Error Handling**, **File Structure**.

### 2.3 Self-contained and decomposed
- A prototype lives entirely in its own folder. It must not import from another prototype. It can use `components/ui`, `lib/controls`, `lib/utils`, and npm packages.
- Never write one giant file. Keep `page.tsx` thin (~60 lines). Split out:
  - `types.ts`: shared types
  - `data.ts`: mock data, constants, config, control schema
  - pure logic files (`geometry.ts`, `search.ts`, `utils.ts`): no React, so they are testable
  - one file per meaningful UI component, with a descriptive name
- Namespace everything that is global: localStorage keys (`pg:<slug>:*`), API routes (`/api/<slug>/*`), SVG/DOM ids (`<slug>-...`).

### 2.4 Design system
- Always use `components/ui` and design tokens: `bg-background`, `text-foreground`, `bg-card`, `bg-muted`, `text-muted-foreground`, `bg-primary`, `border-border`, `fill-foreground`, `stroke-border`, and so on. In SVG, use `className="fill-…"` / `stroke-…` and `fillOpacity`. For gradient stops, use `className="[stop-color:var(--background)]"`.
- Never hardcode colors: no `bg-black`, no `text-white`, no hex/rgb/oklch values, no inline color styles.
- **Read the component source in `components/ui/` before you use a prop.** These components are shadcn `base-nova` on **Base UI, not Radix**. Known differences:
  - Use the `render` prop for composition, not `asChild`. Example: `<SheetTrigger render={<Button />}>`.
  - `Slider` takes an **array**: `value={[n]}`. If you pass a number, it renders two thumbs. `onValueChange` gives `number | number[]`.
  - `Switch` uses `checked` / `onCheckedChange`.
  - Button sizes are `xs|sm|default|lg|icon|icon-xs|icon-sm|icon-lg`. They are smaller than 44px, so add `className="h-11"` / `size-11` for touch targets.
- Components import `cn` from the `cn` package (shadcn's clsx + tailwind-merge). `@/lib/utils` re-exports it.

### 2.5 Control panels
- Anything with tunable parameters (speed, color, size, count) gets a control panel, not inputs spread around the page.
- Use `lib/controls`:
  ```ts
  // data.ts
  export const controlSchema = defineControls({
    speed: { type: "number", label: "Speed", min: 0, max: 10, step: 0.5, default: 3 },
    trails: { type: "boolean", label: "Trails", default: true },
    mode: { type: "select", label: "Mode", options: ["a", "b"], default: "a" },
  });
  // root component
  const controls = useControls(SLUG, controlSchema);           // persisted at pg:<slug>:controls
  <PrototypeShell panel={<ControlPanel controls={controls} />}>…</PrototypeShell>
  ```
  You get Reset and Randomize for free. **Every control panel has both.** `PrototypeShell` puts the panel in a sticky side column on `lg+`, where it never covers the subject. On mobile, it puts the panel in a bottom sheet behind a 44px floating button.
- If you need a new control type, add it to `lib/controls` (types, logic, panel field). Do not fork the library inside a prototype.

### 2.6 Clean and minimal by default
- Start with a single centered column (`max-w-2xl mx-auto`). Do not add sidebars, split panels, or many tabs unless the owner asks.
- Build only what the owner asked for. Do not add dashboards, charts, or views that nobody requested.
- Use fewer elements. Every element must justify its existence. Use plain badges, not colorful ones. Do not add decorative icons.
- Keep interface copy minimal. Remove captions that repeat labels, and hints that nobody needs.

### 2.7 Mobile first
- Everything must work at 375px wide, with no horizontal scroll.
- Tap targets are at least 44×44px.
- On mobile, buttons show only an icon. Labels appear from `sm:` up (`<span className="hidden sm:inline">`), and the button keeps an `aria-label`.
- No hover-only interactions. Every hover state needs a visible touch equivalent (`active:` states, tap toggles).
- Code blocks wrap (`whitespace-pre-wrap break-words`). Nothing scrolls horizontally.
- Modals need visible prev/next buttons or swipe on mobile, not only keyboard shortcuts.
- Use `h-dvh`/`min-h-dvh`, not `h-screen`, and respect `env(safe-area-inset-*)` for fixed elements.
- Inputs use `text-base` on mobile (≥16px), so that iOS does not zoom.

### 2.8 Light and dark mode
- Design dark-first. Light mode must also work, through tokens.
- Never hardcode a `dark` class on a page. The theme is global.
- Use `useTheme()` / `resolvedTheme` only when behavior must change by theme, not only color. Example: canvas or WebGL colors. In that case, read the CSS variables with `getComputedStyle(document.documentElement).getPropertyValue("--foreground")` instead of hardcoding values.

### 2.9 Motion
- Rows or sections that the user adds or removes animate their height open and closed. Nothing pops in and makes the page jump. (Use `grid-template-rows: 0fr → 1fr` transitions, or the `Collapsible`/`Accordion` components.)
- Use smooth deceleration curves (`ease-out`, `cubic-bezier(0.22,1,0.36,1)`). Do not use bouncy overshoot.
- Respect `prefers-reduced-motion` (`motion-reduce:` utilities, or a `matchMedia` hook. See `road-scroll/use-scroll-progress.ts`).
- Verify that animations actually run. Check computed styles (`getComputedStyle(el).transitionDuration`/`animationName`) in the browser. `tw-animate-css` is imported in `globals.css`. If a utility class does nothing, its CSS is not loaded.

### 2.10 AI-backed prototypes
- Call models server-side, through `app/api/<slug>/…/route.ts`. Never expose keys to the client, and never use `NEXT_PUBLIC_` keys. Keys go in Vercel env vars and `.env.local` (gitignored).
- If a model generates UI or layout, put explicit layout constraints in the system prompt (max columns, no wide tables). Defensive CSS is a backup, not the fix.
- Parse JSON from model output defensively: extract the first `{…}` block, then validate it.
- Always wrap API routes in try/catch, and return the correct status codes (400 bad input, 401/403, 502 upstream failure, 500).
- Default to the latest capable models (for Anthropic: `claude-opus-5-5` / `claude-sonnet-5-5` / `claude-haiku-5-5`). Write the choice in `HOW_IT_WORKS.md`.

### 2.11 Storage
- Wrap all `localStorage` access in try/catch. Use `storage` / `storageKey` from `lib/controls`.
- Load on mount (`useEffect`), never during server render.
- Namespace keys per prototype: `pg:<slug>:<name>`.

### 2.12 Thumbnails
- A new prototype, or any visual change → regenerate that prototype's thumbnails in the same commit: `npm run thumbnails -- <slug>`.
- A global style change (globals.css, tokens, shared components) → regenerate all thumbnails: `npm run thumbnails`.
- Other flags: `npm run thumbnails -- a b c` (several), `-- --missing` (only prototypes without both images), `--no-build` (reuse the current `.next`).
- **Open the captured images and check them before you commit.** A stale or broken thumbnail is worse than none. A missing thumbnail shows a "No preview yet" tile. It never breaks the build.

### 2.13 Public prototypes and share previews
- Public prototypes are served at `/p/<slug>`, with no login. Private or unknown slugs return **404** (not a login redirect), so private names do not leak. `/thumbnails/<slug>-*`, `/og/<slug>.*`, and `/api/<slug>/*` are also open only for public slugs (`lib/public-paths.ts`).
- When you make a prototype public (only on explicit request), **always** create share assets in the same commit: run `npm run og -- <slug>`. This writes `public/og/<slug>.png` (1200×630) and `public/og/<slug>.mp4` (a scroll-through video, h264, needs `ffmpeg`). Look at both. `app/p/[slug]/page.tsx` then emits absolute `og:image`, `og:video`, and Twitter tags automatically.
- The `/p/` route has no back link and no gallery chrome. The prototype must make sense on its own.

## 3. Workflow rules

- Work on a branch. Never commit straight to `main`. Push, and open a pull request when you are done. The PR triggers a build check and a Vercel preview deployment.
- Before you finish, run `npm run check` (= `lint` + `typecheck` + `build`). Do not open a PR if one of these fails.
- End every task by posting the preview link (`<preview-url>/prototypes/<slug>`, or `/p/<slug>` if the prototype is public).
- Install new dependencies inside `playground/` (`npm i <pkg>`). This is the app root. Use npm, not pnpm or yarn.
- Next.js 16 differs from older versions: `proxy.ts` replaces `middleware.ts`, `params` is a `Promise` (`await params`), and `PageProps<"/route">` / `LayoutProps` are global types generated by `next typegen`. Read `node_modules/next/dist/docs/` before you use an API that you are not sure about.
- When something goes wrong and you fix it, **add the lesson to §4 below** in the same PR, so that the mistake does not happen again. This file must grow over time.

## 4. Lessons learned

- `npx`-spawned servers ignore SIGTERM and keep stdout pipes open, so scripts hang forever. Spawn `node_modules/.bin/next` with `detached: true`, and kill the process group (`process.kill(-pid)`). (`scripts/lib-server.mjs`)
- A portrait SVG with `preserveAspectRatio="… slice"` crops the top in landscape containers (thumbnails, desktop). Compute the viewBox from the container aspect, as in `road-scroll/geometry.ts → viewBoxFor`.
- Open Graph URLs must be absolute. `metadataBase` resolves `og:image`, but not `og:video`, so build absolute URLs yourself.
- `cacheComponents` is turned off in `next.config.ts` on purpose. With it on, every `params`/`cookies` access needs a Suspense boundary, and prototypes break easily.
- Vendored `components/ui` and `hooks/` fail `react-hooks/set-state-in-effect`. That rule is relaxed only for those paths, in `eslint.config.mjs`. It stays on for prototype code.
- After a Playwright upgrade, run `npx playwright install chromium`, or the capture scripts fail at launch.
